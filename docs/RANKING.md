# Ranking & Metric Explanations

This document explains the composite ranking produced by the **merge** stage of
the pipeline and how every metric shown in the ranking is extracted and
calculated.

---

## 1. When does ranking happen?

Ranking is generated by `run_merge()` when you run:

```bash
python main.py --merge --name <experiment>
```

For example:

```bash
python main.py --merge --name exp_mech_yolov5s
```

The merge step:

1. Reads the baseline CSV `outputs/detection/<name>/comparison.csv`.
2. Reads every retrain CSV `outputs/detection/<name>_retrain_*/comparison.csv`.
3. Tags each row's Run ID with a strategy prefix (`base_`, `tt0.90_`, `whole_`, …).
4. Merges them into `<name>_merged/comparison.csv`.
5. **Ranks the rows by a composite score** and writes
   `<name>_merged/ranking.csv`.
6. Regenerates the comparison plots.

The ranking itself is implemented in `_rank_and_report()` in `../main.py`, using:

- `RANKING_WEIGHTS` — the weights applied to each metric.
- `_composite_score()` — the score calculation.
- `_freeze_ratio_value()` / `_freeze_ratio_label()` — the freeze-ratio column.

---

## 2. Ranking output (ranking.csv)

Each row of `ranking.csv` has the following columns:

| Column | Meaning |
|--------|---------|
| `Rank` | 1 = best, based on the composite `Score` |
| `Run ID` | Tagged identifier, e.g. `tt0.90_mech_yolov5_small` |
| `Experiment` | Source experiment folder |
| `Freeze Ratio` | TinyTrain freeze ratio (or `nan` if none) |
| `Score` | Composite score, 0–100 (higher = better) |
| `Delta vs Baseline` | `Score` minus the baseline row's `Score` |
| `mAP50`, `mAP50-95` | Mean Average Precision |
| `Precision`, `Recall`, `F1-Score` | Precision / recall / F1 |
| `Inference (ms)` | Pure inference latency |
| `Total (ms/img)` | Preprocess + inference + postprocess |
| `Parameters` | Number of model parameters |
| `Size (MB)` | On-disk weight file size |

**Freeze Ratio** is derived from the Run id tag:

| Tag | Freeze Ratio |
|------|--------------|
| `base_*` | `nan` (no retrain) |
| `tt0.20_*` | `0.2` |
| `tt0.50_*` | `0.5` |
| `tt0.90_*` | `0.9` |
| `whole_*` | `0.0` (whole model retrained, nothing frozen) |

If a run has no freeze information the `Freeze Ratio` cell is left blank/NaN.

## 3. How each metric is extracted

Metrics come from the **evaluation** stage
(`../evaluation/detector/yolo_evaluator.py`) when each model is validated against
the shared `valid/` split with Ultralytics.

| Metric (CSV) | Source | Calculation |
|--------------|--------|-------------|
| `mAP50` | `box.map50` | Mean Average Precision at IoU **0.50**, `×100` |
| `mAP50-95` | `box.map` | Mean AP **averaged over IoU 0.50 → 0.95**, `×100` |
| `Precision` | `box.mp` | Mean precision `×100` |
| `Recall` | `box.mr` | Mean recall `×100` |
| `F1-Score` | computed | `2·P·R / (P + R)`, using the precision/recall above |
| `Inference (ms)` | `speed["inference"]` | Neon inference latency per image in ms |
| `Total (ms/img)` | `speed` | `preprocess + inference + postprocess` |
| `Parameters` | `model.parameters()` | `sum(p.numel() for p in model.parameters())` |
| `Size (MB)` | weight file | `file_size_bytes / (1024 × 1024)`, rounded to 2 dp |

All accuracy percentages are rounded to 2 decimal places.

---

## 4. How the composite score is calculated

The composite score puts every run on the same normalized 0–100 scale and
weights each metric. Seven metrics participate:

```python
RANKING_WEIGHTS = {
    "mAP50-95":     0.30,
    "mAP50":        0.15,
    "Precision":    0.10,
    "Recall":       0.10,
    "F1-Score":     0.10,
    "Inference (ms)": 0.15,
    "Size (MB)":      0.10,
}
```

Weights sum to `1.0`:

### 4.1 Normalization

For each metric `c`, across all merged rows:

```
lo = min(row[c] for row in rows)
hi = max(row[c] for row in rows)
```

Then each row is normalized to `[0, 1]` where `1` is the best value:

- **Accuracy metrics** (higher is better)
  `norm = (value - lo) / (hi - lo)`
- **Speed/size metrics** (lower is better)
  `norm = (hi - value) / (hi - lo)`

If all rows have the same value (`hi == lo`), that metric's normalization is
`1.0` (neither penalized nor boosted).

### 2.2 Weighted sum

```
score = Σ( weight[c] × norm[c] )
Score = score × 100
```

The `Score` column therefore ranges 0–100. Accuracy is the dominant factor
(`mAP50-95` alone carries 30% of the weight, and the mAP family ~45%), while
latency and model size together carry 25% to reward efficient models.

### 4.3 Delta vs baseline

```
Delta vs Baseline = Score − baseline_score
```

A positive delta means the run outperforms the baseline overall; negative means
it is worse.

---

## 5. Highlights printed

After ranking, the console prints three extra callouts:

- **Best overall** — the run with the highest `Score` (`ranked[0]`).
- **Best accuracy** — the run with the highest `mAP50-95`.
- **Fastest** — the run with the lowest `Inference (ms)`.

## 6. Worked example

Using your real `exp_mech_yolov5s` experiment, the merge produced:

```
  Rank Run ID                     Freeze mAP50-95  mAP50  F1 Inf(ms) Score Δ vs base
    1  tt0.90_mech_yolov5_small       90%    61.63  85.81 81.98 1.11   87.5    +61.5
    2  tt0.50_mech_yolov5_small       50%    59.86  85.20 81.07 1.01   67.5    +41.6
    3  whole_mech_yolov5_small         0%    58.43  84.23 79.62 0.94   32.9     +6.9
    4  tt0.20_mech_yolov5_small       20%    58.77  84.09 79.52 1.07   32.8     +6.9
    5  base_mech_yolov5_small          —     59.25  83.64 79.99 1.95   25.9     +0.0

  Best overall : tt0.90_mech_yolov5_small (score 87.5)
  Best accuracy: tt0.90_mech_yolov5_small (mAP50-95 61.63)
  Fastest      : whole_mech_yolov5_small (0.94 ms)
```

For this dataset, **TinyTrain with 90% freeze** is the overall winner, and the
**whole** retrain is the fastest.
